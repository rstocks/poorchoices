# Poor Choices

> A growing archive of regrets, in the writers' own words.

An [Eleventy](https://www.11ty.dev/) site (v3.1, ESM) for the public cataloguing of private misjudgements.

## Quick start

Requires **Node 18+** (Netlify deploy uses Node 20).

```bash
npm install
npm start        # dev server with live reload at http://localhost:8080
npm run build    # static build into _site/
```


## Writing a new regret

Drop a Markdown file into `src/posts/` with the following front matter:

```yaml
---
title: "I named my band 'The Variables'"
dek: "A short, slightly mortifying summary."
author: "Your name, or a credible alias"
date: 2026-04-18
regret: 8                # 1–10
would_do_again: false
lesson: "If you have to explain it, the gig is going badly."
cost: "$40 and my dignity."
tags: ["music", "hubris", "public-shame"]
---

Body copy here, in Markdown.
```

`posts.json` already wires the layout, the structural `posts` tag, and the permalink for you, so you just write. The structural `posts` tag is merged with any `tags` you add — write your own tags as a flat list. Use lowercase, hyphenated, two-to-four-tags-per-entry.

## Tags

The site auto-generates:

- `/tags/` — an index of every tag with entry counts (uses the `tagList` collection in `.eleventy.js`)
- `/tags/{tag}/` — a paginated listing page per tag (one page per real tag, via the `tag.njk` template)

The `realTags` filter strips the structural `posts` tag so templates only render meaningful ones. Tag URLs are slugified, so `public-shame` lives at `/tags/public-shame/`.

## Feeds

Atom feeds, generated by the official [`@11ty/eleventy-plugin-rss`](https://www.11ty.dev/docs/plugins/rss/) plugin:

- `/feed.xml` — every entry, newest first
- `/tags/{tag}/feed.xml` — one feed per tag, also auto-generated via pagination

Discovery `<link rel="alternate">` tags are injected on every page; tag-listing pages additionally advertise their tag-scoped feed. The footer carries a visible "Subscribe via RSS" link.

## Deployment (Netlify)

`netlify.toml` is committed at the project root with the build command, publish directory (`_site`), Node version, security headers, an Atom-feed content-type override, and a tiny redirect. Just point a Netlify site at the repo and it should build on the first push.

### The submission form

`src/contribute.njk` uses **Netlify Forms** — no backend code required.

- `data-netlify="true"` on the `<form>` is what Netlify's post-processor scans for during deploy
- `name="regret-submission"` is the form identifier you'll see in the Netlify dashboard under **Forms**
- A hidden `<input name="form-name">` repeats the name in the POST body (Netlify needs both)
- `data-netlify-honeypot="bot-field"` + a visually-hidden `bot-field` input catches a lot of spam quietly
- `action="/thanks/"` redirects to a custom success page (`src/thanks.njk`)

To wire up notifications: in the Netlify UI, **Site settings → Forms → Form notifications**, add an email recipient or a Slack/webhook outgoing notification for the `regret-submission` form.

Submissions appear in the Netlify dashboard with all the fields (`name`, `primary-tag`, `title`, `regret-rating`, `would-do-again`, `lesson`, `email`, `body`) ready to skim. The free tier covers 100 submissions/month, which is hopefully enough.

## Design

- Type: **EB Garamond** (body + headings) + **JetBrains Mono** (metadata, UI chrome)
- Palette: warm paper `#f5efe4`, ink `#1c1a17`, brick-red accent `#8a2a1f`
- One stylesheet, no JS framework, no build step beyond 11ty itself

## Editorial principles

1. No advice columns. If we knew, we wouldn't be here.
2. No takedowns. You may only volunteer your own regrets, not others'.
3. No redemption arcs. Sometimes the kayak is just in the living room.
